# Renderer prerequisites, October 29, 2026

This phase has no genuine game launcher and changes no production runtime,
supervisor enforcement, acceptance evidence, authorization or breakpoint.
Results and identities are in
`out/recovery/renderer-prerequisites-20261029-01/`.

`phase.py` preserves inputs, reads the actual sandbox configuration and accepted
capability observations, binds a narrow 237-call initialization profile in a
separate runtime, and builds an unlaunched experimental client. Each admitted
tuple has independent accepted GPU evidence; the full fixture sample matrix is
not an allowlist. The bridge checks the original callsite, renderer/device
identity, all 53 capability words, exact configuration fields, non-editor state,
stage/stream bounds, identity matrix bytes and NULL resource identities.

The target is windowed 1540x945, anisotropy 1, trilinear mip filtering, bias -0.5,
eight texture stages, sixteen NULL streams and FVF 2. Native and generated full
ResizeViewport bodies agree for flags 16 using project-owned object dependencies
and real USER32 windows. The added MoveWindow adapter admits only the decoded
Window.dll callsite, owned registered HWND, DPI 96, measured style/menu, existing
window position, adjusted 1540x945 client size and repaint TRUE. Native x86/x64
and actual translated registered callbacks agree; focused callback/accessibility
regressions and rejection guards remain active. Full historical WNDPROC equality
is still FAILED.

The saved Caps2 bit 0x20000 makes gamma reachable. Original x86 arithmetic and
generated arithmetic produce identical 1536 input bytes for the actual configured
gamma/brightness/contrast. That CPU-only result is separate from device/desktop
gamma qualification and does not waive the strict x87 failure. The integrated
candidate keeps SetGammaRamp guarded until physical qualification succeeds.

`service.py` adds one fixed restoring gamma family to the existing persistent
supervisor framework in a separate home, `out/desktop-prerequisites`. It reuses
the unchanged physical gate, mapped-module collector, immutable candidate pins,
durable queue/ledger, Job, cancellation and watchdog. No queue-selected command
or genuine family is accepted. A parent-owned guard saves and validates each
active desktop display ramp, retains original bytes, and restores and rereads
them even if the child fails. The child separately saves/restores the D3D ramp,
checks configured input/readback bytes, and captures actual void-call ABI/FPU
and last-error behavior. There are three fixed variants: native x86, native x64,
and translated x64. It never runs graphics during build or qualification.

The existing service catalog cannot execute gamma. After successful local
qualification, the owner must press Ctrl+C in the old fixture console, then run
from an ordinary PowerShell on the physical desktop:

```powershell
& 'E:\Unreal2-Port-Investigation\.venv\Scripts\python.exe' -B -I 'E:\Unreal2-Port-Investigation\experiments\xrt\tests\renderer_prerequisites\service.py' serve
```

Type `AUTHORIZE RESTORING GAMMA FIXTURES` at that local console. The extension
holds the original service lock as well as its own, preventing concurrent
desktop test services. This starts no game and grants no genuine authorization.
Codex can then submit the identified prepared candidate using `service.py submit`.

After physical gamma qualification, a later integration step must add only the
qualified exact gamma bridge, rerun combined regressions, and build/identify a
